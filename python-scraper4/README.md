# Python Scraper 4 — با ظاهر و امکانات پروژهٔ Node.js

این پوشه پروژهٔ **اسکرپر پایتون** است که از مخزن `fazilatma/amphp`، برنچ
`arena/01a06ac3-amphp` آورده شده و ظاهر و امکانات آن با پروژهٔ **Node.js**
(`cloudflare-scraper4` در برنچ `arena/01a0aa17-new`) یکسان شده است.

## ظاهر

فایل `worker-src/dashboard.ts` پروژهٔ Node دو رشتهٔ بزرگ دارد: `DASHBOARD`
(کل HTML و CSS) و `DASHBOARD_JS` (اسکریپت کلاینت). این دو **عیناً** و بدون
هیچ تغییری در `ui/dashboard.html` و `ui/dashboard.js` ذخیره شده‌اند. بنابراین
نوار بالا، کشوی تنظیمات (drawer)، شش تب پایین، رنگ‌ها، فونت و همهٔ متن‌های
فارسی دقیقاً مثل پروژهٔ Node است.

| مسیر | توضیح |
| --- | --- |
| `/` | فروشگاه عمومی فارسی و واکنش‌گرا |
| `/store-admin` | مدیریت فروشگاه، سفارش، درگاه و وب‌هوک |
| `/ui` | داشبورد جدید مدیریت استخراج (ظاهر Node) |
| `/classic` | رابط کلاسیک پایتون — دست‌نخورده باقی مانده |

## امکانات

`ui_bridge.py` حدود ۹۵ اندپوینتی را که داشبورد Node صدا می‌زند روی Flask ثبت
می‌کند و آن‌ها را به مدل دادهٔ پایتون نگاشت می‌دهد:

* **پروفایل‌ها** — `GET/POST /api/profiles`، حذف، محصولات، خروجی CSV.
  تبدیل دوطرفهٔ بدون تلفات بین `Profile` نود و شمای پایتون انجام می‌شود
  (`detailImage` ↔ `detail_selectors.image`، `query_page` ↔ `query`،
  `priceMode/priceValue` ↔ `profile_rules` و …).
* **اجرا** — `/api/profiles/<id>/scrape|run|extract` همان
  `scrape_live_worker` پایتون را اجرا می‌کند؛ `/sync` به
  `start_profile_dispatch` وصل است.
* **صف و کارها** — وظایف زندهٔ پایتون (`LIVE_TASKS`) به شکل `Job` نود
  ترجمه می‌شوند تا تب «درون‌ریزی» و نوار فعالیت کار کند.
* **اتصال‌ها و تنظیمات** — ووکامرس، باسلام و هوش مصنوعی؛ کلیدهای محرمانه
  به‌صورت `***` برگردانده می‌شوند و فقط در صورت ارسال مقدار تازه بازنویسی
  می‌شوند.
* **ابزار سلکتور** — تست سلکتور، پیشنهاد خودکار، تست منبع.
* **پشتیبان** — خروجی/ورودی تنظیمات و درون‌ریزی پروفایل‌های PHP.

* **مقصدها** — نمای کلی، فهرست محصولات، تغییر وضعیت و حذف در ووکامرس،
  و پیدا کردن محصولات تکراری در مقصد.
* **نگهداری** — جدول مغایرت منبع/مقصد، فهرست محصولات بدون تصویر، و
  پیش‌نمایش محصولات اضافهٔ مقصد.
* **هوش مصنوعی** — گفت‌وگو، عیب‌یابی اتصال، رأی‌دهی و جدول امتیاز مدل‌ها،
  و اجرای آزمایشی؛ همه روی `ai_chat()` واقعی بک‌اند.
* **باسلام** — فهرست گفت‌وگوها و پیام‌ها، پیشنهاد دسته با هوش مصنوعی.
* **یادگیری دسته** — ثبت، آزمایش و درون‌ریزی نگاشت عنوان → دسته.
* **گیت‌هاب** — فهرست برنچ‌ها، فهرست فایل‌ها و خواندن محتوای فایل.

همهٔ رابط‌ها روی **یک فایل داده** (`scraper4_data.json`) کار می‌کنند و هرکدام
شمای بومی خودش را می‌بیند، پس می‌توان بین فروشگاه، `/classic` و `/ui`
جابه‌جا شد.

## فروشگاه عمومی و پرداخت (۱۰.۲۲۱)

ماژول `storefront.py` محصولات `saved_products` همهٔ پروفایل‌ها را در ویترین
نمایش می‌دهد. قیمت از `source_price` دوباره با قواعد فعلی همان پروفایل محاسبه
می‌شود و پس از آن تعدیل اختیاری فروشگاه اعمال می‌شود؛ قیمت یا مبلغ ارسال‌شده
از مرورگر هیچ‌گاه مبنای ثبت سفارش نیست.

* سبد در مرورگر نگهداری می‌شود، اما موجودی، قیمت، ارسال و جمع نهایی در سرور
  دوباره کنترل می‌شوند. سفارش دارای idempotency key، توکن دسترسی هش‌شده،
  تاریخچه و رزرو موجودی است.
* زرین‌پال با API v4 و دیجی‌پی با OAuth/UPG رسمی متصل‌اند. ترب‌پی و درگاه
  سفارشی adapter قراردادی دارند تا endpoint و template تحویلی پذیرنده بدون
  حدس‌زدن قرارداد API وارد شود.
* credentialها در پاسخ عمومی وجود ندارند. مقدارهای ثبت‌شده با AES-GCM و کلید
  محلی دارای permission `0600` رمز می‌شوند؛ برای استقرار مدیریت‌شده می‌توان
  `SCRAPER_STORE_SECRET_KEY` و credentialهای زیر را به‌صورت environment تعریف
  کرد. فایل `*.store-key` عمداً وارد Git/بکاپ عمومی نمی‌شود؛ آن را جداگانه و
  امن نگه دارید، چون بدون این کلید داده‌های رمز‌شده قابل بازیابی نیستند.
  credentialهای پشتیبانی‌شده: `SCRAPER_ZARINPAL_MERCHANT_ID`، `SCRAPER_DIGIPAY_CLIENT_ID`،
  `SCRAPER_DIGIPAY_CLIENT_SECRET`، `SCRAPER_DIGIPAY_USERNAME` و
  `SCRAPER_DIGIPAY_PASSWORD`.
* callback فقط پس از verify سمت سرور سفارش را پرداخت‌شده می‌کند و اجرای مجدد
  آن idempotent است. در محیط واقعی، «آدرس عمومی HTTPS» را در `/store-admin`
  تنظیم کنید.
* گیرندهٔ باسلام URL محرمانه، Bearer اختیاری، سقف payload و deduplication دارد.
  ساخت/ثبت آن از بخش «وب‌هوک باسلام» انجام می‌شود. رخدادهای رسمی پیام، سفارش،
  پارسل، محصول و تجربهٔ خرید در پنل ثبت و قابل مشاهده‌اند.

مراجع رسمی قراردادها: [زرین‌پال v4](https://www.zarinpal.com/docs/paymentGateway/connectToGateway)،
[دیجی‌پی UPG](https://www.mydigipay.com/developers/docs/upg/) و
[وب‌هوک باسلام](https://developers.basalam.com/docs/services/webhook). API عمومی
ترب‌پی برای پذیرندهٔ اختصاصی منتشر نشده و endpoint/credential آن پس از قرارداد
از پنل یا پشتیبانی ترب دریافت می‌شود؛ به همین دلیل adapter ترب‌پی عمداً
پیکربندی‌پذیر است و endpoint حدسی در کد وجود ندارد.

اگر `SCRAPER_PASSWORD` تنظیم باشد، فقط ویترین، سفارش‌های token-protected،
callback پرداخت و گیرندهٔ secret-protected عمومی می‌مانند؛ `/store-admin`،
`/classic`، `/ui` و APIهای مدیریت همچنان Basic Auth می‌خواهند.

## کشف خودکار سلکتورها (۱۰.۱۷۸)

اگر سلکتورهای یک پروفایل **خالی یا ناقص** باشد، استخراج دیگر با خطای
«هیچ محصولی استخراج نشد» تمام نمی‌شود؛ برنامه روی همان صفحهٔ دریافت‌شده
خودکار سلکتورها را پیدا می‌کند، همان‌جا راستی‌آزمایی می‌کند و نتیجه را در
**سلکتورهای دستی پروفایل** ذخیره می‌کند:

* دو گذر متوالی مثل نسخهٔ Node (`ensureListSelectors` در
  `worker-src/scraper.ts`): اول الگوهای آمادهٔ فروشگاه‌ها (ووکامرس و
  مانند آن)، بعد **تحلیل ساختاری** — کارت‌های محصول از خوشه‌بندی
  پیوند+تصویر بر اساس امضای `tag.class` پیدا می‌شوند و سلکتور
  عنوان/قیمت از داخل همان کارت‌ها رأی‌گیری می‌شود.
* راستی‌آزمایی دقیقاً مثل خواندن واقعی استخراج: ظرف در کل صفحه شمرده
  می‌شود ولی عنوان/قیمت/لینک/تصویر باید **داخل خود کارت‌ها** پیدا شوند.
* سلکتور دستیِ کامل (هر پنج فیلد فهرست پرشده) هرگز دست نمی‌خورد؛ در
  مجموعهٔ ناقصِ کارآمد هم فقط فیلدهای **خالی** پر می‌شوند.
* صفحهٔ جزئیات هم همین رفتار را دارد: اولین صفحهٔ محصول واقعی، فیلدهای
  خالی (توضیح، قیمت، گالری، تنوع، برند، اس‌کی‌یو و…) را پر و ذخیره می‌کند.
* عیب‌یابی استخراج مراحل «کشف خودکار سلکتورها» و «ذخیرهٔ خودکار
  سلکتورها» را گزارش می‌کند و دکمهٔ «پیشنهاد خودکار سلکتورها»
  (`POST /api/suggest-selectors`) حالا واقعاً کار می‌کند.

آزمون بازگشتی این بخش (بدون شبکه، با فیکسچر محلی):

```bash
python3 python-scraper4/tools/test_auto_selectors.py
```

## قرارداد تطبیق با Node.js

فهرست API مرجع Node.js نسخهٔ `1.211.1+` (کامیت
`dfd6cc7fede31622ac15be90c15eb21b7f549ece`) در
`parity-manifest.json` ثابت شده است. بررسی اول، پوشش هر ۱۶۷ route، نبود route
تکراری، نسخه، changelog و assetهای لازم را بدون شبکه کنترل می‌کند. بررسی دوم
قراردادهای رفتاری و عملیات پرخطر را با adapterهای شبکهٔ mockشده اجرا می‌کند؛
هیچ فروشگاه، سرویس Push، مدل AI یا ریپوی GitHub واقعی تغییر نمی‌کند.

```bash
python3 python-scraper4/tools/check_node_parity.py
python3 python-scraper4/tools/test_node_parity_contracts.py
```

## نسخه‌بندی

نسخهٔ برنامه در `APP_VERSION` داخل `scraper4.py` است و **هر تغییر نسخه باید
یک ردیف تازه در بالای `CHANGELOG` همان فایل اضافه کند**. این گزارش در
`/api/changelog` سرو می‌شود و پنل «گزارش تغییرات کد» در داشبورد آن را
مستقیماً نمایش می‌دهد.

برای اینکه این قاعده فراموش نشود، بررسی خودکار اضافه شد:

```bash
python3 python-scraper4/tools/check_version.py
```

بررسی می‌کند که `APP_VERSION` با بالاترین ردیف یکی باشد، نسخه‌ها تکراری
نباشند، ترتیب نزولی باشد و هر ردیف تاریخ و عنوان و حداقل یک مورد داشته باشد.

نسخهٔ دیپلویر جداست: `DEPLOYER_VERSION` در `deployer4.py`.

## دستیار هوشمند (Agent)

دستیار یک حلقهٔ چندمرحله‌ای است: از مدل می‌پرسد قدم بعدی چیست، **یک ابزار
واقعی** را اجرا می‌کند، نتیجه را به مدل برمی‌گرداند و تا رسیدن به پاسخ نهایی
یا سقف گام‌ها ادامه می‌دهد. دکمه‌های توقف/ادامه در checkpoint کار می‌کنند.

ابزارهای در دسترس: `list_profiles`، `list_products`، `list_jobs`،
`start_scrape`، `fetch_page`، `stats`.

پرامپت‌ها و تاریخچهٔ اجراها در `scraper4_data.json` ذخیره می‌شوند.

## به‌روزرسانی خودکار

هر ۶۰ ثانیه برنچ جاری بررسی و در صورت وجود کامیت تازه با `git merge --ff-only`
به‌روز می‌شود. اگر تغییر محلی ذخیره‌نشده وجود داشته باشد اجرا نمی‌شود.

بخش «🔄 نسخهٔ کد» در منوی همبرگری همین چرخه را مدیریت می‌کند (۱۰.۱۷۹):

  از `/api/deployer/branches` اجرا می‌شود؛ همان endpoint نسخهٔ در حال اجرا،
  نسخهٔ هر برنچ (با کش ۱۰ دقیقه‌ای)، وضعیت جدیدتر/قدیمی‌تر/برابر، برنچ فعلی
  و پیکربندی deploy را برمی‌گرداند.
* منبع پیش‌فرض به‌روزرسانی همین فورک است: `fazilatma/new` و برنچ
  `arena/01a0bd3f-new` با مسیر `python-scraper4/scraper4.py`
  (ثابت‌های `DEPLOY_DEFAULT_*` در `scraper4.py`).
* روی Termux دستور `scraper4 update` علاوه بر کد، **خودِ دستور scraper4 را هم
  تازه می‌کند** — همهٔ دستورها داخل `tools/install_termux.sh` (تابع
  `write_launcher`) تعریف شده‌اند و update همان فایل را از مخزن pull شده
  دوباره اجرا می‌کند. `scraper4 restart` هم اضافه شده است.

## موتورهای استخراج

فهرست موتورها دیگر ثابت نیست. `/api/engines` هنگام بالا آمدن صفحه بررسی
می‌کند کدام کتابخانه روی همین سرور نصب است و فهرست را می‌سازد؛ موتورهای
نصب‌نشده با برچسب «نصب نیست» نمایش داده می‌شوند تا گزینهٔ مرده انتخاب نشود.

| مرحله | موتور | کاربرد |
| --- | --- | --- |
| دریافت | `requests` | سریع، سایت‌های ساده |
| دریافت | `httpx` | HTTP/2، سریع |
| دریافت | `curl_cffi` | دور زدن اثرانگشت TLS/JA3 — برای سایت‌های ضدبات |
| دریافت | `cloudscraper` | چالش‌های کلودفلر |
| دریافت | `playwright` | رندر کامل جاوااسکریپت (SPA) |
| دریافت | `selenium` | مرورگر واقعی، کندتر |
| پارس | `jsonld` | دادهٔ ساختاریافتهٔ Product |
| پارس | `next_data` | `__NEXT_DATA__` نکست/ناکست |
| پارس | `metadata` | OpenGraph |
| پارس | `script_json` | JSON داخل تگ script |
| پارس | `heuristic` | تشخیص خودکار کارت محصول |
| پارس | `lxml` / `selectolax` | پارس سریع (selectolax چند برابر سریع‌تر) |

موتورهای نود اصلی (Cheerio، HTMLRewriter، Puppeteer و …) حذف شدند چون در
پایتون وجود ندارند و انتخابشان بی‌اثر بود.

پنل‌های اختیاری‌ای که بک‌اند پایتون معادلی برایشان ندارد (عامل هوشمند،
جدول امتیاز AI، push نوتیفیکیشن و …) پاسخ خالی معتبر می‌دهند تا رابط بدون
خطا بالا بیاید.

## اجرا

```bash
cd python-scraper4
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
PORT=8080 .venv/bin/python scraper4.py
```

سپس `http://localhost:8080/ui` را باز کنید.

برای نصب روی سرور (VPS، systemd، Apache/Nginx با پیشوند `/put/`) راهنمای
کامل در **[INSTALL.md](INSTALL.md)** است.

> هنگام انتقال به سرور، `scraper4.py` و `ui_bridge.py` و پوشهٔ `ui/` باید
> **کنار هم** کپی شوند؛ در غیر این صورت داشبورد جدید بالا نمی‌آید و فقط
> رابط کلاسیک کار می‌کند.
