# 🚀 پنل استقرار گیت‌هاب — `deploy.php` v3.0

یک ابزار عمومی برای انتقال فایل از گیت‌هاب به هاست، بدون کپی و پیست دستی.
**هر فایلی** از **هر برنچی** از **هر ریپویی** را با **نام و پوشهٔ دلخواه** روی هاست نصب می‌کند.

## تازه در نسخهٔ ۳

| قابلیت | توضیح |
|---|---|
| 🩺 **بررسی سلامت** | نشان وضعیت در نوار بالا. دسترسی‌ها، افزونه‌ها، فضای دیسک و **اتصال واقعی به گیت‌هاب** (با زمان پاسخ و سهمیهٔ باقی‌مانده) را می‌سنجد و برای هر مشکل راه‌حل می‌دهد. |
| 📝 **پیش‌نمایش تفاوت** | پیش از نصب نشان می‌دهد دقیقاً چند خط اضافه و چند خط حذف می‌شود، با نمایش خطوط تغییریافته. |
| 📊 **وضعیت همهٔ کارها** | هر مقصد با گیت‌هاب مقایسه می‌شود: به‌روز / نسخهٔ جدید / وجود ندارد / خطا. |
| ☁️ **بکاپ رمزنگاری‌شده** | کل ورک‌اسپیس هاست با AES-256-GCM به گیت‌هاب می‌رود (از v2.x، در نسخهٔ ۳ تثبیت شد). |

---

## نصب (یک‌بار برای همیشه)

۱. فایل `deploy.php` را در ریشهٔ سایت (یا هر پوشه‌ای) آپلود کنید
۲. در مرورگر بازش کنید: `https://yoursite.com/deploy.php`
۳. یک رمز عبور تعیین کنید — تمام

نیازی به ویرایش کد نیست. همه‌چیز از داخل پنل تنظیم می‌شود.

## تب‌های پنل

### 📦 استقرار
سه بخش ساده:

**① مبدأ** — ریپو را وارد و «بارگذاری» را بزنید. فهرست برنچ‌ها می‌آید و با انتخاب برنچ،
همهٔ فایل‌های آن با قابلیت **جستجوی زنده** نمایش داده می‌شوند. کافی است چند حرف تایپ کنید.

**② مقصد** — اینجا همه‌چیز قابل تنظیم است:

| گزینه | توضیح |
|---|---|
| پوشهٔ مقصد | خالی = کنار `deploy.php` · یا `tools` یا `a/b/c` (خودکار ساخته می‌شود) |
| نام فایل نهایی | خالی = همان نام مبدأ · یا هر نام دلخواه |
| chmod | حفظ وضعیت فعلی، ۶۴۴، ۶۴۰، ۶۰۰ یا ۷۵۵ |
| حداقل حجم | جلوی نصب فایل ناقص را می‌گیرد |
| بررسی نحوی PHP | فایل معیوب هرگز نصب نمی‌شود |
| بکاپ پیش از نصب | نسخهٔ فعلی حفظ می‌شود |

زیر نام فایل، **وضعیت لحظه‌ای فایل روی هاست** را می‌بینید: حجم، تاریخ، هش و اینکه
قابل نوشتن هست یا نه.

**③ اجرا** — دو دکمه:
- **🔍 بررسی** — می‌گوید چه اتفاقی می‌افتد، بدون اینکه چیزی را تغییر دهد
- **🚀 نصب کن** — واقعاً انجام می‌دهد

سه دکمه دارید:
- **🔍 بررسی** — می‌گوید چه اتفاقی می‌افتد، بدون تغییر
- **📝 تفاوت‌ها** — خطوط افزوده و حذف‌شده را نشان می‌دهد *(جدید در v3)*
- **🚀 نصب کن** — واقعاً انجام می‌دهد

نتیجه به‌صورت مرحله‌به‌مرحله نمایش داده می‌شود (دانلود ✓ حجم ✓ نحو ✓ بکاپ ✓ نصب ✓).

### ⭐ کارهای ذخیره‌شده
هر ترکیبی را با یک نام ذخیره کنید و بعداً با یک کلیک اجرا کنید.
با دکمهٔ «اجرای همه» می‌توانید چند فایل را هم‌زمان به‌روز کنید.

دکمهٔ **📊 وضعیت همه** *(جدید در v3)* هر مقصد را با گیت‌هاب مقایسه می‌کند و
در یک جدول نشان می‌دهد کدام به‌روز است، کدام نسخهٔ جدید دارد و کدام مشکل دارد —
بدون اینکه چیزی نصب شود.

### 🗄️ بکاپ‌ها
فهرست همهٔ نسخه‌های قبلی با تاریخ و حجم. هر کدام را می‌توانید **بازگردانی** کنید.
(هنگام بازگردانی، از وضعیت فعلی هم بکاپ گرفته می‌شود.) ۲۰ نسخهٔ آخر نگه داشته می‌شود.

### 📜 تاریخچه
۱۰۰ عملیات آخر: چه چیزی، کِی، موفق یا ناموفق، با چه پیامی.

### 🩺 بررسی سلامت *(جدید در v3)*
در تب تنظیمات و همچنین با کلیک روی نشان بالای صفحه. بررسی می‌کند:

- نسخهٔ PHP، وجود cURL و OpenSSL
- قابل نوشتن بودن پوشه و فضای آزاد دیسک
- سطح دسترسی فایل تنظیمات و وضعیت پوشهٔ بکاپ
- **اتصال واقعی به گیت‌هاب** با زمان پاسخ و سهمیهٔ باقی‌مانده
- قابل نوشتن بودن مقصد همهٔ کارها

نشان بالای صفحه 🟢 سالم / 🟡 هشدار / 🔴 خطا را نشان می‌دهد و برای هر مشکل
راه‌حل مشخص می‌دهد.

### ⚙️ تنظیمات
ریپو و برنچ پیش‌فرض، توکن گیت‌هاب (برای ریپوی خصوصی)، تغییر رمز،
توکن API و وضعیت سیستم (نسخهٔ PHP، دسترسی نوشتن، cURL).

## چه چیزی از سایت شما محافظت می‌کند

فایل روی هاست **فقط وقتی** جایگزین می‌شود که همهٔ این مراحل موفق باشند:

1. دانلود با کد ۲۰۰
2. حجم بالاتر از حد تعیین‌شده — جلوی دانلود ناقص
3. شروع محتوا با `<?php` — جلوی ذخیرهٔ صفحهٔ خطای HTML
4. **بررسی کامل نحوی** با `token_get_all()` — فایل معیوب رد می‌شود
5. بکاپ موفق از نسخهٔ فعلی
6. نوشتن در فایل موقت → تأیید مجدد هش → **جایگزینی اتمیک** با `rename()`

اگر هر مرحله شکست بخورد، عملیات لغو می‌شود و **فایل فعلی دست‌نخورده می‌ماند**.

این‌ها تست شده‌اند، نه ادعا: فایل با خطای نحوی، فایل ناقص، HTML به‌جای PHP و خطای ۴۰۴ —
در هر چهار مورد نصب متوقف شد و فایل سالم **بایت‌به‌بایت** باقی ماند.

### امنیت
- پنل با **رمز عبور** محافظت می‌شود (`password_hash` + `hash_equals`)
- **path traversal** مسدود است: `../`، `../../etc` و مسیرهای مطلق همگی داخل ریشه محدود می‌شوند (تست شده)
- `.deploy-config.json` و لاگ با `chmod 600` و `.htaccess` از دسترسی وب محافظت می‌شوند
- پوشهٔ `_backups/` هم با `.htaccess` بسته است
- رمز و توکن هرگز داخل HTML صفحه قرار نمی‌گیرند

## اجرای خودکار

**از طریق وب** (برای وب‌هوک یا سرویس‌های زمان‌بندی):
```
https://yoursite.com/deploy.php?action=run_jobs&api_token=TOKEN
```
توکن را از تب تنظیمات کپی کنید. با `&dry=1` فقط بررسی می‌کند.

**از طریق cron** (توکن لازم نیست):
```bash
# همهٔ کارها
*/30 * * * * /usr/bin/php /home/user/public_html/deploy.php

# فقط یک کار خاص
*/30 * * * * /usr/bin/php /home/user/public_html/deploy.php "اسکریپر اصلی"
```

## ریپوی خصوصی

یک [Personal Access Token](https://github.com/settings/tokens) با دسترسی `repo` بسازید
و در تب تنظیمات وارد کنید. برای حذفش، عبارت `__CLEAR__` را وارد کنید.

## نکات

- اگر پیام «قابل نوشتن نیست» دیدید، سطح دسترسی پوشه را روی `755` بگذارید.
- برای امنیت بیشتر می‌توانید فایل را با نامی غیرقابل‌حدس آپلود کنید
  (مثل `deploy-8f3k2.php`) — همه‌چیز همچنان کار می‌کند.
- فایل‌های حالت (`.deploy-config.json`, `.deploy-log.json`, `_backups/`) در `.gitignore`
  هستند و هرگز commit نمی‌شوند.
