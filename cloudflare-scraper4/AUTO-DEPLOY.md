# 🤖 دیپلوی خودکار با GitHub Actions

با هر بار که من تغییری push می‌کنم (یعنی بعد از هر پرامپت)، گیت‌هاب خودکار
`deploy.php` روی هاست شما را صدا می‌زند و کد به‌روز می‌شود. **بدون هیچ کاری از طرف شما.**

---

## چرا این روش و نه اسکریپت جاوااسکریپت؟

یک نکتهٔ مهم: **من نمی‌توانم بعد از پایان پاسخم کدی اجرا کنم.** محیط کاری من
موقتی است و به محض تمام شدن نوبت خاموش می‌شود. پس هر اسکریپتی که اینجا بنویسم
و اجرا کنم، لحظه‌ای بعد از بین می‌رود.

اما گیت‌هاب سرور دائمی دارد. GitHub Actions روی زیرساخت گیت‌هاب اجرا می‌شود،
با هر push فعال می‌شود و رایگان است (برای ریپوی عمومی نامحدود).

---

---

## ⚠️ یک گام که فقط از دست شما برمی‌آید

گیت‌هاب به دلایل امنیتی اجازه نمی‌دهد یک اپلیکیشن (یعنی من) فایل workflow بسازد
یا تغییر دهد — این محدودیت درستی است، چون در غیر این صورت هر اپ متصل به ریپو
می‌توانست کد دلخواه روی سرور گیت‌هاب اجرا کند.

پس فایل آماده را در مسیر `deploy-setup/deploy.yml.txt` گذاشتم و **شما باید
یک‌بار آن را جابه‌جا کنید**. ساده‌ترین راه، از داخل خود گیت‌هاب:

1. فایل [`deploy-setup/deploy.yml.txt`](deploy-setup/deploy.yml.txt) را باز کنید
2. دکمهٔ **Copy raw file** را بزنید
3. به `Add file → Create new file` بروید
4. نام فایل را دقیقاً این بگذارید: `.github/workflows/deploy.yml`
5. محتوا را بچسبانید و **Commit** کنید

یا اگر گیت محلی دارید:

```bash
git pull
mkdir -p .github/workflows
cp deploy-setup/deploy.yml.txt .github/workflows/deploy.yml
git add .github/workflows/deploy.yml
git commit -m "Add deploy workflow"
git push
```

بعد از این یک‌بار، همه‌چیز خودکار است و دیگر لازم نیست تکرارش کنید.

---

## راه‌اندازی (سه دقیقه، یک‌بار برای همیشه)

### گام ۱ — توکن نصب‌کننده را بردارید

پنل `deploy.php` را باز کنید → تب **⚙️ تنظیمات** → بخش **🤖 اجرای خودکار** →
مقدار **توکن API** را کپی کنید.

اگر هنوز کاری تعریف نکرده‌اید، اول در تب **📦 استقرار** فایل را تنظیم و با دکمهٔ
**⭐ ذخیره به‌عنوان کار** ذخیره کنید. workflow همهٔ کارهای ذخیره‌شده را اجرا می‌کند.

### گام ۲ — دو Secret در گیت‌هاب بسازید

به این آدرس بروید:

```
https://github.com/fazilatma/code/settings/secrets/actions
```

روی **New repository secret** بزنید و این دو را اضافه کنید:

| نام | مقدار |
|---|---|
| `DEPLOY_URL` | `https://yoursite.com/deploy.php` |
| `DEPLOY_TOKEN` | توکنی که در گام ۱ کپی کردید |

> ⚠️ حتماً از **Secrets** استفاده کنید، نه Variables. مقدار Secret بعد از ذخیره
> دیگر قابل مشاهده نیست و در لاگ‌ها هم به‌صورت `***` نمایش داده می‌شود.

### گام ۳ — تمام

از این به بعد هر push خودکار دیپلوی می‌کند.

## دیدن نتیجه

به تب **Actions** در گیت‌هاب بروید:

```
https://github.com/fazilatma/code/actions
```

هر اجرا با ✅ یا ❌ مشخص است و با کلیک روی آن، پاسخ کامل هاست را می‌بینید.

**اجرای دستی:** در همان تب، workflow را انتخاب کنید و **Run workflow** را بزنید.

## پیام‌های خطا

اسکریپت هر حالت خطا را جداگانه تشخیص می‌دهد:

| پیام | معنی |
|---|---|
| `DEPLOY_URL یا DEPLOY_TOKEN تنظیم نشده است` | گام ۲ را انجام نداده‌اید |
| `ارتباط با هاست برقرار نشد` | آدرس اشتباه است یا فایروال هاست جلوی گیت‌هاب را گرفته |
| `هاست کد 403 برگرداند` | توکن اشتباه است |
| `هاست کد 404 برگرداند` | مسیر `deploy.php` درست نیست |
| `نصب‌کننده خطا گزارش کرد` | دیپلوی شروع شد ولی ناموفق بود — متن پاسخ را در لاگ ببینید |

---

## نکات

- workflow فقط وقتی اجرا می‌شود که `scraper4.php` یا `deploy.php` تغییر کرده باشد،
  پس کامیت‌های بی‌ربط باعث دیپلوی الکی نمی‌شوند.
- `concurrency` تنظیم شده تا دو دیپلوی هم‌زمان روی هاست انجام نشود.
- در صورت قطعی موقت شبکه، دو بار تلاش مجدد می‌کند.
- تمام محافظت‌های `deploy.php` سر جایشان هستند: بررسی نحوی PHP، بکاپ خودکار،
  و جایگزینی اتمیک. اگر فایل معیوب باشد، نصب لغو می‌شود و سایت شما دست‌نخورده می‌ماند.

---

## اگر ترجیح می‌دهید خودکار نباشد

فایل `.github/workflows/deploy.yml` را حذف کنید یا در تب Actions آن را Disable کنید.
همچنان می‌توانید دستی از پنل `deploy.php` یا از داخل خود اسکریپر (بخش «🔄 نسخهٔ کد»
در منوی همبرگری) به‌روزرسانی کنید.

**توصیهٔ من:** اگر روی سایت زندهٔ پرترافیک کار می‌کنید، حالت دستی امن‌تر است چون
دقیقاً می‌دانید چه زمانی کد عوض می‌شود. برای محیط توسعه، خودکار راحت‌تر است.
