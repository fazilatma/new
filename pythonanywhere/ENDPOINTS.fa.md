# اتصال پوستهٔ اصلی — نسخهٔ 1.18.0

مسیر ورود به رابط: `/php-ui` (پس از ورود). داشبورد پیش‌فرض هنوز عوض نشده است.
منبع بررسی‌شده: PHP **10.646**، commit `aec65b64fbee0db82e06b1c6b7a684c7741b879d`.
متن اصلی HTML/CSS/JS با ابزار vendor و هش ثابت نگه داشته شده؛ تغییرات اجرایی در adapterهای جداست.

## قراردادهای محدود و قابل مشاهده

`GET /api/php-ui/capabilities` فهرست به‌روز قراردادها را می‌دهد؛ **تست اجرایی نیست**.
هر عملیات زیر روی `POST /api/php-ui/read` یا `POST /api/php-ui/write` اجرا می‌شود:

```json
{"action":"نام عملیات","query":{},"fields":{}}
```

همهٔ مقادیر query/fields باید رشته باشند؛ ذخیرهٔ پروفایل موجود، revision دریافتی از load را نیز می‌خواهد.
فقط نشست مرورگر مدیر و CSRF معتبر مجازند؛ API bearer حتی همراه نشست نیز اجازهٔ این رابط را ندارد.
کودک فقط پیام به والد می‌دهد؛ والد مبدأ/پنجرهٔ دقیق را کنترل و هر نوشتن را تأیید می‌کند.

| گروه | قراردادهای متصل | پوشش تست |
|---|---|---|
| خواندن پایه | `app_ready`, `load_profile`, `load_connections`, `start_product_stats`, `extract_queue_status`, `whoami` | Flask/SQLite؛ انتخاب واقعی پروفایل، نمایش نتایج و آمار با اسکریپت‌های اصلی |
| وضعیت صف/کار | `woo_queue_status`, `bsl_queue_status`, `tasks_list`, `poll_woo`, `poll_bsl`, `poll_basalam`, `poll_extract` | خواندن بدون تغییر DB؛ شمارندهٔ واقعی، خطای امن، ردیف یتیم؛ حداکثر ۱۰۰ کار اخیر |
| شرح قرارداد | `python_capabilities`, `python_contracts` | سازگاری فهرست‌ها با endpoint capabilities؛ صراحتاً full_php_parity=false |
| ذخیره/استخراج | `save_profile`, `python_enqueue` | revision/تداخل کار فعال، حفظ محصول/قیمت خام/شناسهٔ مقصد، ذخیرهٔ صریح و ثبت استخراج بدون اجرا |
| ارسال/زنجیره | `python_send_enqueue`, `python_manual_sync` | اعتبارسنجی اتمی همهٔ مقصدها، غرفهٔ ذخیره‌شده و pin شناسهٔ باسلام، جلوگیری از صف/رزرو تکراری و رقابت همزمان؛ اجرای worker با HTTP شبیه‌سازی‌شده |
| کنترل صف | `python_queue_control` | مکث/ادامه/لغو با شناسهٔ صریح؛ مکث محدود به پروفایل+نوع؛ حفاظت ردیف پایان‌یافته و ارسال مبهم؛ مکث/لغو در حین HTTP شناسهٔ ثبت‌شده را نگه می‌دارد |
| پاک‌کردن ردها | `python_queue_clear` و control=`delete` | فقط done/cancelled؛ حذف checkpoint مرتبط؛ حفظ failed/فعال و محصولات |
| پروفایل | `python_profile_duplicate`, `python_profile_delete` | کپی فقط تنظیمات، بدون محصول/شناسه؛ حذف صریح محلی فقط پس از پایان/لغو کارهای فعال/ناموفق؛ مقصد دست‌نخورده |

۱۸ قرارداد خواندن و ۱۰ قرارداد نوشتن متصل‌اند (شامل سلامت runtime و قراردادهای صفحهٔ شروع 1.18.0). `python_open_panel` صرفاً پیام UI است،
نه API عمومی نوشتن. اکشن ناشناخته/نامتصل **۵۰۱** می‌گیرد؛ ذخیرهٔ خودکار قدیمی مجاز نیست.
نام‌های قدیمی مانند `woo_backend`, `bsl_backend`, `manual_sync`, `cron_run` و
heartbeat/feedback، به worker یا کران پایتون نگاشت نشده‌اند. callbackهای زمان‌بندیِ
صف باسلام غیرفعال‌اند؛ فقط worker/کران تنظیم‌شده کار را claim می‌کند.

## پنل امن در همان صفحه، نه redirect

همبرگری اصلی دکمهٔ اتصال به پنل امن دارد؛ «تنظیمات اجرایی» و اطلاعات اتصال از همان منو → «اطلاعات رابط و ابزارهای امن پایتون» هم در دسترس‌اند.
کنترل‌های محرمانهٔ قدیمی با فرم‌های واقعی والد جایگزین می‌شوند. این موارد همان کنترلرهای
داشبورد پایتون‌اند، نه فرم‌های نمایشی تازه:

| پنل | endpointهای اصلی | وضعیت اعتبارسنجی |
|---|---|---|
| ووکامرس/باسلام | `/api/connections/*`, `/api/basalam/vendors` | boot همهٔ کنترلرها و ذخیرهٔ واقعی Woo در همین میزبان؛ مجموعهٔ موجود، CRUD غرفه/ماسک/حفظ کلید را نیز تست می‌کند |
| بکاپ تنظیمات | `/api/settings/export`, `/api/settings/inspect`, `/api/settings/preview`, `/api/settings/import` | کنترلر اصلی انتقال و تست‌های roundtrip/inspect/apply روی DB موقت؛ این بکاپ پوشهٔ هاست، محصول یا صف نیست |
| حساب/کران/worker/نسخه/رندر | `/api/system/status`, `/api/cron/config`, `/api/worker/*`, `/api/platform/*`, `/api/updates/*`, `/api/deploy/config`, `/api/connections/render` | پنل‌ها داخل میزبان باز می‌شوند؛ تست‌های اصلی هر زیرسامانه APIهای خارجی را mock می‌کنند؛ در تولید فعال‌سازی یا تغییر کران انجام نشد |
| تنظیمات/پاک‌سازی پروفایل | `/api/profile-settings/<id>`, `/preview`, `/cleanup-preview`, `/cleanup` | ذخیره/پیش‌نمایش واقعی در میزبان؛ تست امضای stale/CSRF/پاک‌سازی در مجموعهٔ پروفایل؛ proof پاک‌سازی هرگز به iframe نمی‌رود |
| آزمایش سلکتور/موتور | `/api/selectors/preview`, `/api/extraction/*` | آزمایش سلکتور از همین پنل با پارسر واقعی و HTML شبیه‌سازی‌شده؛ مقایسهٔ موتورها فقط پس از submit صریح |
| تمام نتایج/جزئیات | `/api/products`, `/api/products/overview`, `/api/products/<id>` و export | قرارداد موجودِ صفحه‌بندی/فیلتر/جست‌وجو/جزئیات؛ نمایش واقعی در میزبان، بدون سقف کلی ۱۰۰۰ نمای اصلی |
| کنترل امن صف | `/api/php-ui/read`, `/api/php-ui/write`, `/api/extraction/status`, `/api/extraction/step` | mount همان DOM کنترل استخراج؛ ادامهٔ ارسال failed فقط پس از بررسی مقصد و تأیید دستی |

نام‌های wildcard در جدول خانوادهٔ endpoint هستند، نه ادعای وجود تک‌تک مسیرهای دلخواه.
مرجع دقیق مسیرها، routeهای برنامه و تست‌های هر ماژول است.

## محدودیت و مرز آزمون

- **همهٔ اکشن‌های PHP متصل یا تست نشده‌اند.** شمارش lexical قدیمی در parity ledger به
  commit مرجع خودش مربوط است؛ نام‌های پویا/کدهای تعبیه‌شده inventory اجرایی کامل نیستند.
- مدیریت سفارش/چت/هوش مصنوعی، تغییرات تنوع/رسانه/دسته‌بندی، انتخابگر بصری، موجودی و
  ماتریس زندهٔ مقصد، بکاپ کامل هاست و قراردادهای مدیریتی قدیمی هنوز کامل نیستند.
- ارسال روی **همهٔ محصولات ذخیره‌شدهٔ پروفایل** است، نه محصول‌های فیلترشدهٔ iframe.
  کپی پروفایل محصولات و شناسه‌ها را کپی نمی‌کند؛ حذف محلی برگشت‌ناپذیر است.
- پاسخ ناموفق ارسال ممکن است پس از موفقیت مقصد قطع شده باشد. قبل از ادامه، مقصد و
  شناسهٔ محصول را تطبیق دهید؛ exactly-once تضمین نمی‌شود. مکث/لغو HTTP در حال پرواز را پس نمی‌گیرد.
- تست‌های DOM با **jsdom** و اسکریپت‌های کامل اصلی انجام شده‌اند؛ Chromium/PHP CLI در
  محیط موجود نیست. به‌ویژه نمایش، opaque-origin/CSP در مرورگر واقعی و محدودیت‌های شبکهٔ
  حساب PythonAnywhere باید جداگانه بررسی شوند؛ داشبورد پیش‌فرض تا آن زمان باقی می‌ماند.
- فقط DBهای موقت، fixture مبدأ و مقصد شبیه‌سازی‌شده استفاده شدند. هیچ پروفایل خصوصی،
  توکن تولید، صف تولید یا ارسال فروشگاه واقعی برای این تست‌ها استفاده نشد.

اعتبارسنجی این انتشار: **۵۶۲ آزمون Python + ۹۵ آزمون DOM + ۲۲ آزمون تازه‌سازی**.
فایل‌های اصلی افزوده‌شده: `test_php_ui_operations.py` و پنج رگرسیون جدید در
`php_original_ui.test.cjs`؛ این آمار تعداد تست‌هاست، نه تعداد تمام قابلیت‌های PHP.

## اصلاح بارگذاری در 1.17.1

منبع PHP10.646/aec65b6 دوباره بررسی شد و تغییر نکرده است؛ متن اصلی و sandbox
دست‌نخورده‌اند. تست جدید از **Chromium واقعی 153 با Playwright 1.65**، Flask و
دیتابیس موقت استفاده می‌کند. timerها، رخدادهای load/focus و CSP فعال‌اند؛
`--disable-web-security` و `allow-same-origin` استفاده نشده‌اند.

علت‌های بازتولید و اصلاح‌شده:

1. دسترسی `navigator.serviceWorker` در مبدأ opaque خطای SecurityError می‌داد.
   helper چرخهٔ عمر اکنون مطابق قرارداد اصلی، نبود worker را با `null` برمی‌گرداند؛
   هیچ worker ثبت نمی‌شود و موفقیت جعلی تولید نمی‌شود.
2. bridge قبلی فقط json/text داشت؛ کد اصلی `response.headers.get` و بدنه/clone را
   نیز لازم دارد. پاسخ مرورگر اکنون Response واقعی JSON است. AbortSignal، پایان
   مهلت و پاسخ دیررس نیز pending را پاک می‌کنند.
3. امکانات منتقل‌نشده هنگام شروع ده‌ها درخواست پس‌زمینه می‌ساختند. فهرست صریح
   pollerهای نامتصل، شامل AI/چت/ماتریس و heartbeatهای قدیمی، اکنون **محلی با خطای
   ۵۰۱ رد می‌شود** و به بک‌اند نمی‌رود؛ اطلاعات تشخیصیِ صرفاً نام عملیات و شمارش
   در `S4NativeDiagnostics.blockedBackground()` قابل مشاهده است. برای این مسیرها
   هیچ ok:true، گزارش جعلی یا payloadِ «صف خالی» ساخته نشده است. درخواست مستقیم
   API ناشناخته همچنان ۵۰۱ است؛ دستور دستی قدیمی cron نیز اجازهٔ اجرای کار ندارد.
4. بارگذاری پروفایل دیگر برای هر سلکتور به سایت مبدأ درخواست نمی‌فرستد. دکمهٔ
   تست اصلی، آزمایشگاه امن واقعی را باز می‌کند؛ آزمایش فقط با کلیک صریح اجرا می‌شود.
5. `runtime_health` به قرارداد خواندن اضافه شد: VERSION واقعی Python، نسخهٔ جداگانهٔ
   پوسته و processed=false. چراغ سلامت دیگر ادعا نمی‌کند PHP روی سرور پاسخ داده است.
6. HTML/JSON نامعتبر یا نشست منقضی‌شدهٔ endpoint به خطای خوانا تبدیل می‌شود؛ بدنهٔ
   خطای سرور به iframe تحویل داده نمی‌شود.

اکنون **۱۶ قرارداد خواندن** وجود دارد (۱۵ قبلی + runtime_health)؛ ۸ قرارداد نوشتن
بدون تغییر هستند. اجرای آزمون مرورگر در Linux:

```sh
npm ci --prefix tools/browser-tests
npm test --prefix tools/browser-tests
```

در سناریوی آزموده‌شدهٔ بارگذاری/انتخاب پروفایل/تب‌ها/منو/تست سلکتور:
**۰ خطای JavaScript و ۰ خطای HTTP**، بدون تغییر digest دیتابیس و بدون ثبت کار.
این تأیید همهٔ پروفایل‌های خصوصی، همهٔ امکانات یا مرورگرها نیست.
یک warning قدیمی از خود منبع، با متن `Version mismatch` و شرط ثابت `v8.22`، هنوز
وجود دارد؛ console و error handler برای پنهان‌کردنش فیلتر نشده‌اند. نسخهٔ واقعی در
بالای صفحه، runtime_health و healthz قابل بررسی است. امکانات نامتصل همچنان نامتصل‌اند.

اعتبارسنجی نهایی 1.17.1: **۵۶۴ Python + ۹۸ DOM + ۲۲ تازه‌سازی + ۱ سناریوی Chromium واقعی = ۶۸۵ تست موفق**.


## نمایش تمام فضای مرورگر در 1.17.2

- `/php-ui` بدون padding به‌جامانده از داشبورد و بدون رزرو ۹۰ پیکسل برای ناوبری والد، تمام viewport پویا را به رابط اصلی می‌دهد؛ اسکرول فقط در همان رابط است.
- نوار توضیحات والد به dialog قابل بستن با Escape منتقل شده و از همبرگری اصلی (`python_open_panel: help`) باز می‌شود. قرارداد help فقط نمایش UI است، نه API نوشتن یا اعطای اختیار جدید.
- محدودیت عرض ۱۴۰۰ پیکسل و خطای reset شدن padding بالای دسکتاپ در adapter بیرونی اصلاح شده؛ فایل upstream حتی یک بایت تغییر نکرده است. تب‌های دسکتاپ بالا و تب‌های موبایل پایین، مطابق رفتار منبع می‌مانند.
- دکمهٔ بازیابی هنگام خرابی بارگذاری قابل مشاهده است؛ پس از `app_ready` موفق فقط با فوکوس صفحه‌کلید ظاهر می‌شود، نه به‌صورت پوشش دائمی روی دکمه‌های اصلی.
- Chromium واقعی در ۱۹۲۰×۱۰۸۰، ۱۲۸۰×۸۰۰، ۹۰۰×۷۰۰، ۸۹۹×۷۰۰، ۳۹۰×۸۴۴، ۳۲۰×۵۶۸ و حالت افقی ۸۴۴×۳۹۰، اندازهٔ دقیق iframe، نمایان‌بودن عنوان، کلیک هر پنج تب، منوی راهنما و ثابت‌ماندن DB را بررسی می‌کند. شبیه‌سازی viewport اثبات تست دستگاه واقعی iOS یا همهٔ مرورگرها نیست.
- این مرحله فقط همسانی نمایش/دسترسی را بهتر می‌کند؛ امکانات نامتصل قبلی، ارسال واقعی فروشگاه و جایگزینی داشبورد پیش‌فرض همچنان تأیید نشده‌اند.

مرحلهٔ native فقط شناسهٔ استخراج متعلق به پروفایل داده‌شده را در حالت waiting claim می‌کند. قفل مشترک worker/کران، حداکثر یک گام، timeout شبکهٔ ۸ ثانیه، بودجهٔ ۱۵ ثانیه و فاصلهٔ دستی ۴۵ ثانیه حفظ شده‌اند. قدیمی‌ترین صف ارسال یا استخراج پروفایل دیگر اجرا نمی‌شود. busy/throttled به معنی اجرای مرحله نیست و صریح گزارش می‌شود.

خطای 403، rate limit، renderer، ساختار پاسخ و خطای کلی از گزارش دسته‌بندی‌شده نمایش داده می‌شود؛ raw error/HTML/توکن/URL خصوصی و warningهای قدیمی به کودک داده نمی‌شود. استخراج خالی «صفر محصول» نشان می‌دهد، نه موفقیت ظاهری. اجرای ناموفق مانع ساخت استخراج تکراری می‌شود تا کار قبلی صریح ادامه یا لغو شود. ذخیرهٔ تنظیمات هم‌زمان با کار فعال همچنان برای ایمنی رد می‌شود.

**محدودیت باقی‌مانده:** انتخابگر بصری iframe سایت، همگام‌سازی دوره‌ای/ماتریس کامل PHP، موجودی/مغایرت زنده و عملیات محصولات متفرقهٔ مقصد، و کپی محصولات همراه پروفایل کامل نشده‌اند؛ ادعای فعال‌بودن همهٔ امکانات یا همهٔ حساب‌های واقعی نداریم. استخراج و ارسال روی پروفایل‌های خصوصی production توسط عامل اجرا نشده است.
