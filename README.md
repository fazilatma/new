# 📊 حسابدار فروش | مدیریت سفارش‌ها و سود (باسلام + سایت فروشگاهی)

برنامه حسابداری حرفه‌ای، فارسی و راست‌چین برای فروش **واسطه‌ای** (دراپشیپینگ) با پشتیبانی از:
- 🛍 **باسلام** با **چند غرفه**
- 🌐 **سایت فروشگاهی**
- 📅 **تقویم و تاریخ شمسی** در همه‌جا
- 📈 تحلیل سود و زیان **روزانه / هفتگی / ماهانه / سالانه** با نمودارهای جذاب
- 🧾 صدور فاکتور، خروجی اکسل، بکاپ JSON
- ☁️ اجرا روی **Cloudflare Workers** + دیتابیس **D1**

## ✨ امکانات

| بخش | توضیح |
|---|---|
| داشبورد | فروش، هزینه، سود خالص، حاشیه سود، میانگین سبد، روند فروش/سود، سهم منابع، عملکرد غرفه‌ها، پرفروش‌ترین کالاها، آخرین سفارش‌ها |
| ثبت سفارش | نام مشتری، تلفن، شهر، کالا، تعداد، تامین‌کننده، قیمت فروش، هزینه خرید، تخفیف، ارسال، بسته‌بندی، کمیسیون، تبلیغات، سایر هزینه‌ها، وضعیت سفارش و پرداخت، **نوع خرید مشتری (نقدی/قسطی)**، تاریخ شمسی، **محاسبه لحظه‌ای سود** در فرم دو بخشی مشتری/تامین‌کننده + الزام ثبت هزینه و تامین‌کننده در ویرایش |
| گزارش و تحلیل | سود و زیان دوره‌ای (روزانه/هفتگی/ماهانه/سالانه)، عملکرد تامین‌کنندگان، تحلیل کالاها + نمودار |
| غرفه‌ها | مدیریت چند غرفه باسلام با آمار فروش و سود هر غرفه |
| تامین‌کنندگان | مدیریت واسطه‌ها با آمار خرید و سود |
| فاکتور | نمایش و چاپ فاکتور فروش برای هر سفارش |
| حذف تکی و گروهی | انتخاب چندتایی و حذف دسته‌جمعی سفارش‌ها، غرفه‌ها و تامین‌کنندگان |
| رنگ‌بندی ردیف‌ها | رنگ پس‌زمینه هر سفارش بر اساس وضعیت و ثبت هزینه + کلیک روی ردیف برای ویرایش |
| نشان رنگی وضعیت | هر ۶ وضعیت رنگ و آیکون متمایز خود را دارد (در انتظار ⏳ کهربایی، تاییدشده ✅ آبی، ارسال‌شده 🚚 بنفش، تحویل‌شده 📦 سبز، مرجوعی ↩ نارنجی توپر، لغو ✕ رز توپر) |
| نمودارهای زمانی | روند چندخطی تعداد/حجم/سود (تجمعی، تکمیل، لغو، مرجوعی) با راهنمای کلیکی، اسکرول/درگ-پن و بازه ۳/۶/۱۲ماهه/همه، تفکیک کانال فروش |
| داده | خروجی اکسل (CSV)، بکاپ/بازیابی JSON، داده نمونه برای تست |

- 💵 **نوع خرید از تامین‌کننده:** ثبت نقدی/قسطی بودن خرید هر سفارش، با فیلتر در لیست سفارش‌ها و ستون خروجی اکسل.

- 🤖 **پیشنهاد خودکار کمیسیون و ارسال دریافتی** در فرم سفارش (از تعرفه/٪ غرفه، به‌روزشونده با قیمت و تعداد) با حفظ ویرایش دستی.

## 🔗 اتصال خودکار (باسلام + ووکامرس)

از بخش **«اتصال‌ها»** در برنامه:

| اتصال | چه چیزی لازم است | از کجا بگیرید |
|---|---|---|
| 🛍 غرفه باسلام (هر غرفه جداگانه) | Personal Access Token با دسترسی `vendor.parcel.read` | [پنل توسعه‌دهندگان باسلام](https://developers.basalam.com/panel/tokens) |
| 🌐 سایت ووکامرس | آدرس سایت + Consumer Key + Consumer Secret با دسترسی Read | پیشخوان وردپرس ← ووکامرس ← تنظیمات ← پیشرفته ← REST API |

- دکمه **«تست اتصال»** صحت توکن/کلید را بررسی می‌کند و اسم غرفه یا فروشگاه را نشان می‌دهد.
- دکمه **«سینک سفارش‌ها»** سفارش‌های N روز اخیر را وارد حسابداری می‌کند (کد `BL-…` برای باسلام و `WC-…` برای سایت).
- سینک مجدد **تکراری ایجاد نمی‌کند** و **هزینه‌ها/تامین‌کننده‌ای که دستی ثبت کرده‌اید را پاک نمی‌کند** (فقط اطلاعات فروش و وضعیت به‌روز می‌شود).
- 💰 **کارمزد و هزینه ارسال:** باسلام این دو را در API نمی‌دهد؛ کارمزد در سینک از «٪ پیش‌فرض» تنظیمات (جداگانه برای باسلام/سایت) محاسبه و فقط در خانه‌های خالی نوشته می‌شود — مقدار دستی شما هرگز بازنویسی نمی‌شود و سفارش لغوشده کارمزد نمی‌گیرد. هزینه ارسال واقعی بعد از ثبت کد پیگیری از رسید پستی می‌آید؛ تا قبل از آن، عدد دستی شما با سینک مجدد پاک نمی‌شود. پیش‌فرض هزینه ارسال صفر است و فقط رسید واقعی یا عدد دستی آن را پر می‌کند (تخمین تعرفه دیگر داخل هزینه نوشته نمی‌شود).
- 🏪 **تنظیمات هر غرفه:** ٪ کارمزد مخصوص غرفه (با پیشنهاد خودکار از جدول رسمی کارمزد باسلام بر اساس دسته‌بندی) + تعرفه ثابت ارسال تک‌قلمی/چندقلمی (مثلاً ۲۰۰/۲۲۵ هزار تومان). در سینک، ٪ غرفه بر ٪ سراسری اولویت دارد و «ارسال دریافتی از مشتری» به‌عنوان درآمد ثبت می‌شود. جدول رسمی: vendor.basalam.com/landings/commission
- 🔐 توکن‌ها و رمزها فقط در دیتابیس خصوصی شما (D1) ذخیره می‌شوند و هیچ‌وقت به مرورگر ارسال نمی‌شوند.
- ⏰ **سینک خودکار با بازه قابل‌تنظیم:** در کارت اتصال تیک «خودکار» را بزنید و بازه را از همان ردیف انتخاب کنید (۱۵ دقیقه تا ۲۴ ساعت) — ورکر در هر تیک، سفارش‌های ۲ روز اخیر اتصال‌هایی که موعدشان رسیده را سینک می‌کند و سپس وضعیت همه سفارش‌های باز (در انتظار/تاییدشده/ارسال‌شده، هرچقدر قدیمی) را تکی از API می‌خواند و تازه می‌کند — پس لغو یا ردِ دیرهنگام هم در سینک بعدی اعمال می‌شود. (اگر با روش «کپی‌پیست در داشبورد» دیپلوی کرده‌اید، یک‌بار در داشبورد اضافه کنید: ورکر ← Settings ← Triggers ← Cron Triggers ← Add با عبارت `*/15 * * * *`)
- 🔄 دکمه **«سینک همه اتصال‌ها»** همه منابع (باسلام + سایت‌ها) را یکجا سینک می‌کند.
- 🗂 **وضعیت‌های سفارش (داخلی):** در انتظار تایید ⬅️ تایید شده ⬅️ ارسال شده ⬅️ تحویل شده، به‌علاوه مرجوع شده و لغو شده. نگاشت خودکار: هر ۱۲ وضعیت مرسوله باسلام (جدید، در حال آماده‌سازی، ارسال‌شده، اطلاعات ارسال نادرست، نرسیده، ثبت مشکل، درخواست لغو مشتری، درخواست توافق تاخیر، رضایت، عودت وجه کامل، لغو، **درخواست لغو غرفه‌دار**) و وضعیت‌های ووکامرس (pending/on-hold، processing، completed، cancelled/failed، refunded) در هر سینک به این ۶ وضعیت تبدیل و روی سفارش‌های موجود هم به‌روز می‌شوند.
- 🧮 **مبنای حسابداری (واحدی/کلی):** در تنظیمات انتخاب کنید در فرم «مبلغ واحد» وارد کنید یا «مبلغ کل» — در حالت کلی، فرم مبالغ کل را می‌گیرد و خودکار به واحد تبدیل می‌کند؛ ذخیره‌سازی همیشه واحدی است پس گزارش‌ها در هر دو حالت یکسان‌اند و جابه‌جایی حالت هیچ عددی را خراب نمی‌کند.
- 🔢 همه ورودی‌های مالی (فرم سفارش و تعرفه غرفه) جداکننده هزارگان فارسی دارند.
- 🏷 زیر جدول سفارش‌ها، چیپ‌های هر ۶ وضعیت با شمارش هست؛ با کلیک روی هر چیپ آن وضعیت به فیلتر اضافه/کم می‌شود (انتخاب همزمان چند وضعیت؛ «همه» = حذف فیلتر) و سلکت وضعیت خودکار هماهنگ می‌شود.
- 🔍 **یافتن سفارش‌های جامانده:** سینک باسلام صفحه‌به‌صفحه جلو می‌رود و فقط با ۲ صفحه پیاپیِ کاملاً قدیمی می‌ایستد (یک مرسوله قدیمیِ وسط راه دیگر جلوی بقیه را نمی‌گیرد)؛ سفارش تازه‌پرداخت‌شده با تاریخ ایجاد قدیمی هم دیده می‌شود. نتیجه سینک تعداد «بررسی‌شده» را نشان می‌دهد — اگر سفارش جدیدی نیامد، یک‌بار سینک «🌍 همه سفارش‌ها» را بزنید.

## 🚀 اجرا و دیپلوی

### روش صفر: اتصال گیت‌هاب به کلاودفلر (پیشنهادی 🤖) — بدون سکرت، بدون توکن

فقط چند کلیک، فقط یک‌بار. بعد از آن هر Push به‌صورت خودکار دیپلوی می‌شود و هر دیپلوی یک **ورژن** جدید در داشبورد می‌سازد:

1. در داشبورد Cloudflare: **Workers & Pages ← Create ← Connect to Git** ← انتخاب همین ریپو:
   - Production branch: همان شاخه‌ای که کد نهایی در آن است
   - Build command: `npm run build` (بقیه پیش‌فرض) ← **Deploy**
2. ساخت دیتابیس: **Storage & databases ← D1 SQL Databases ← Create** با نام `hesabdar-db`
3. اتصال دیتابیس: لازم نیست! ✅ اتصال دیتابیس داخل کد ثبت شده و با هر دیپلوی خودکار اعمال می‌شود. (اگر قبلاً دستی binding اضافه کرده‌اید، می‌توانید حذفش کنید — اختیاری.)
4. تمام! 🎉 از این به بعد هر Push = یک ورژن جدید، خودکار.

> در صفحه ورکر، تب **Versions** تاریخچه همه ورژن‌ها را نشان می‌دهد و با **Rollback** می‌توانید با یک کلیک به هر ورژن قبلی برگردید.

### روش ۱: دستی با CLI

```bash
npm install
npx wrangler login
npx wrangler login
# (دیتابیس از قبل ساخته شده و اتصال آن داخل wrangler.toml ثبت است)
npm run deploy
# آدرس https://hesabdar.<your-subdomain>.workers.dev آماده است ✅
```

> جدول‌ها به‌صورت خودکار ساخته می‌شوند.

### روش ۲: فقط با داشبورد (بدون ترمینال)

1. دیپلوی کد با روش کپی‌پیست (Edit code).
2. ساخت دیتابیس: **Storage & databases ← D1 SQL Databases ← Create** با نام `hesabdar-db`.
3. اتصال: داخل ورکر ← **Settings ← Bindings ← Add ← D1 database** با نام متغیر `DB` ← انتخاب دیتابیس ← Save و Deploy مجدد.

### تست محلی

```bash
npm install
npm run dev
# مرورگر: http://localhost:8787
```

> ⚠️ دیتابیس **D1 الزامی** است و هیچ حالت موقت/محلی وجود ندارد. در `wrangler dev` دیتابیس به‌صورت محلی شبیه‌سازی می‌شود. اگر از نسخه‌های قبلی داده‌ای در مرورگر دارید، برنامه خودش پیشنهاد «انتقال به فضای دائمی» می‌دهد.

## ☁️ بکاپ ابری خودکار (گوگل درایو / وان‌درایو)

علاوه بر D1، برنامه هر روز یک بکاپ کامل در فضای ابری **خودتان** ذخیره می‌کند. راه‌اندازی (یک‌بار):

**گوگل درایو:**
1. در [console.cloud.google.com](https://console.cloud.google.com) پروژه بسازید و **Google Drive API** را Enable کنید.
2. در **OAuth consent screen** نوع External را کامل کنید و ایمیل خودتان را در Test users اضافه کنید.
3. در **Credentials ← OAuth client ID** نوع Web بسازید و Redirect URI نمایش‌داده‌شده در برنامه (تنظیمات ← بکاپ ابری) را ثبت کنید.
4. Client ID و Secret را در برنامه ذخیره و «اتصال حساب» را بزنید.

**وان‌درایو:**
1. در [portal.azure.com](https://portal.azure.com) مسیر **Microsoft Entra ID ← App registrations ← New registration** با Redirect URI برنامه.
2. مقدار **Application (client) ID** و یک **Client secret** بسازید و در برنامه ذخیره کنید.
3. «اتصال حساب» را بزنید. (مجوز لازم: `Files.ReadWrite`)

بعد از اتصال: بکاپ روزانه خودکار (همراه Cron خودکار) + دکمه «بکاپ فوری» + بازیابی از لیست فایل‌ها.

## 🧮 فرمول سود

```
فروش = قیمت فروش واحد × تعداد − تخفیف
هزینه = (هزینه خرید واحد × تعداد) + ارسال + بسته‌بندی + کمیسیون + تبلیغات + سایر
سود = فروش − هزینه
```

- سفارش **لغو شده**: در آمار لحاظ نمی‌شود.
- سفارش **مرجوعی**: فروش صفر و هزینه‌ها به‌عنوان زیان لحاظ می‌شود (قابل تغییر در داشبورد).
